# Восстановление Docker-томов на team из ночных архивов

Любой Docker-том на хосте team можно вернуть к состоянию одной из последних трёх ночей: достать файл, положить старую версию рядом с текущей или заменить том целиком. В Portainer это делается одноразовым контейнером `alpine:3`, инфра делает то же самое по SSH.

Тома двух ботов этого репозитория (чат поддержки и канал обновлений) перечислены в [README.md](README.md).

## Что нужно знать

- **Архивы.** Каждую ночь в 04:30 UTC (07:30 МСК) каждый том сохраняется файлом `/var/backups/docker-volumes/<том>/<том>_ГГГГММДДTЧЧММССZ.tar.gz` (время в имени по UTC). Хранятся 3 суток, два последних остаются всегда. Лежат на самом team, на том же диске, что и тома. Копия вне team хранится 14 суток (как её получить, см. раздел «Если нужен архив старше 3 суток или team недоступен»).
- **Что в архиве.** Состояние тома на момент ночного запуска. Что менялось позже (например, пользователь добавлен в белый список после 04:30), в нём не будет.
- **Имя тома и архив.** `<том>` везде ниже — полное имя тома из Portainer: Volumes, с именем стека в начале (если том создан стеком), например `tg-spam-wirenboard-chat_tg-spam-wb_data`. Подставляйте его целиком: с одним `tg-spam-wb_data` папки с архивами не найдётся. Какой архив брать: самый свежий из созданных до того, как сломалось. Время в имени по UTC, МСК = UTC + 3. Например, сломалось 12.10 около 10:00 МСК (07:00 UTC): берём архив с 04:30 UTC, `<том>_20261012T043022Z.tar.gz`, а не `<том>_20261012T191746Z.tar.gz`. За сутки архивов может быть больше одного (ночной и ручные запуски), смотрите на время в имени.
- **Доступ.** Нужен вход в Portainer на team с правом создавать контейнеры. Остальным: запрос в инфру (имя тома или стека, на какую дату, достать файл или вернуть том целиком).

## Как сделать в Portainer

Каждое действие из таблицы ниже — один одноразовый контейнер. Создаётся так: Containers → Add container.

1. Name: любое, например `restore-1`. Image: `alpine:3` (Always pull the image выключите: образ уже есть на team).
2. Advanced container settings → Command & logging → Command → Override: команда из таблицы.
3. Volumes → map additional volume, подключения из таблицы: container `/b` типа Bind (в поле host путь на хосте, режим Writable или Read-only: в таблице) и container `/data` типа Volume с томом из таблицы, если он нужен.
4. Restart policy: Never. Нажмите Deploy the container.
5. Через несколько секунд откройте контейнер: статус Exited с кодом 0, вывод на вкладке Logs. Код не 0: дальше не идите, читайте Logs. Закончили: Remove. Следующий контейнер создайте так же: снова Add container, с другими именем, Command и подключениями.

| Действие | Command | container `/b` (Bind): host, режим | container `/data` (Volume): том, режим |
| :-- | :-- | :-- | :-- |
| Какие архивы есть | `ls -l /b/<том>` | `/var/backups/docker-volumes`, Read-only | не нужен |
| Что внутри архива | `tar tzf /b/<том>/<архив>` | `/var/backups/docker-volumes`, Read-only | не нужен |
| Прочитать файл | `tar xzOf /b/<том>/<архив> <путь>` | `/var/backups/docker-volumes`, Read-only | не нужен |
| Положить рядом | `tar xzf /b/<том>/<архив> -C /data` | `/var/backups/docker-volumes`, Read-only | `<том>_old`, Writable |
| Сохранить текущее | `sh -c "umask 077 && tar czf /b/<том>_before-restore_$(date -u +%Y%m%dT%H%M%SZ).tar.gz -C /data ."` | `/var/backups/docker-volumes/restore-safety`, Writable | `<том>`, Read-only |
| Заменить том | `sh -c "tar tzf /b/<том>/<архив> >/dev/null && rm -rf /data/* /data/.[!.]* && tar xzf /b/<том>/<архив> -C /data"` | `/var/backups/docker-volumes`, Read-only | `<том>`, Writable |
| Какие сохранённые копии есть | `ls -l /b` | `/var/backups/docker-volumes/restore-safety`, Read-only | не нужен |
| Вернуть сохранённое | `sh -c "tar tzf /b/<файл> >/dev/null && rm -rf /data/* /data/.[!.]* && tar xzf /b/<файл> -C /data"` | `/var/backups/docker-volumes/restore-safety`, Read-only | `<том>`, Writable |

Каталог `/var/backups/docker-volumes/restore-safety` для копий перед заменой создаёт инфра (права 0700, только root). Если его нет или он не подключается, напишите в инфру.

Путь файла в ночном архиве пишется без `./`, например `tg-spam.db` или `compose/47/docker-compose.yml`; в копиях из `restore-safety` пути начинаются с `./` (`./tg-spam.db`). Текстовый файл читайте в Logs; базы и бинарные файлы доставайте действием «Положить рядом».

### Положить старую версию рядом

Текущий том не меняется, останавливать ничего не нужно. Подходит, чтобы сравнить данные или поднять новый стек со старым томом.

1. Volumes → Add volume: имя `<том>_old`.
2. Контейнер «Положить рядом».
3. В compose нового стека замените описание тома на фрагмент ниже. Стек из Git-репозитория в Portainer не редактируется: создайте новый стек (Web editor) с тем же compose и этой заменой, предварительно остановив прежний.
4. Старая версия больше не нужна: остановите использующий её стек, затем Volumes → `<том>_old` → Remove.

```yaml
volumes:
  <имя тома в compose>:
    external: true
    name: <том>_old
```

Если в стеке несколько томов, повторите шаги 1–2 для каждого тома и подставьте каждый таким же фрагментом. Том, который вы не заменили, новый стек создаст пустым (его имя начнётся с имени нового стека), а том с `external: true` подключит тот же, что у прежнего стека. Поэтому прежний стек перед запуском нового остановите: иначе совпадут тома, порты и имена контейнеров.

### Заменить том на месте

Контейнер «Заменить том» очищает выбранный том: проверьте имя дважды. Перед очисткой он проверяет, что архив читается, поэтому опечатка в имени архива том не стирает. Данные, появившиеся после архива, будут потеряны, поэтому шаг 2 обязателен.

1. Остановите стек тома: Stacks → стек → Stop (имя стека — начало имени тома). Контейнеры вне стека, которые используют том, остановите отдельно.
2. Контейнер «Сохранить текущее». Статус Exited (0), в Logs пусто: можно идти дальше.
3. Контейнер «Заменить том». Код не 0: стек не запускайте и смотрите Logs. Если там «No such file or directory» про архив, том не тронут: поправьте имя архива и повторите. Любая другая ошибка: сразу делайте шаг 5.
4. Запустите стек (Stacks → стек → Start) и пройдите раздел «Проверка после восстановления». Контейнеры «Сохранить текущее» и «Заменить том» удаляйте только после неё.
5. Стало хуже: остановите стек, найдите файл `<том>_before-restore_…` контейнером «Какие сохранённые копии есть», затем контейнер «Вернуть сохранённое» (в Command подставьте имя файла) и запуск стека.

Файлы в `restore-safety` сами не удаляются: когда убедились, что всё работает, удалите их контейнером с Command `rm /b/<файл>` и `/b` = каталог `restore-safety`, Writable.

## Проверка после восстановления

1. Containers: контейнеры стека Up, ни один не Restarting.
2. Логи контейнеров (Containers → контейнер → Logs) без ошибок доступа к данным.
3. Приложение отвечает: например, бот реагирует в чате.
4. Данные соответствуют дате архива.
5. Напишите в чат инфры: том, архив, время. Portainer действий не журналирует, без этого сообщения следа не останется.

Что-то не так: остановите стек, верните сохранённое состояние или возьмите архив другой даты. При сомнениях не действуйте дальше, напишите в инфру.

## Если нужен архив старше 3 суток или team недоступен

Архивы на team живут 3 суток. Копия вне team хранится 14 суток, доступ к ней только у инфры: в архивах секреты стеков. Поэтому напишите в инфру: том или стек, на какую дату и время нужно состояние, достать файл или вернуть том целиком.

Если team работает, инфра достаёт архив из копии и кладёт его в отдельный каталог на team (не в `/var/backups/docker-volumes/<том>/`: ночная чистка удалит оттуда архив старше 3 суток). Дальше те же действия из таблицы, только `/b` — этот каталог, а путь в команде `/b/<архив>`.

Если team недоступен целиком, инфра разворачивает том из архива на другом хосте (`tar xzf` в новый том) и запускает стек; том `portainer` хранит описания стеков, его возвращают первым. Эта процедура целиком ещё не отрабатывалась. Старше 14 суток архивов нет.
